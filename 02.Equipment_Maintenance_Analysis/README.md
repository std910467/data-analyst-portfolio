# 02. Equipment_Maintenance_Analysis

## 專案說明
本專案使用 Microsoft Azure 的 Predictive Maintenance 公開資料，模擬工廠設備維運情境，分析機台故障原因並嘗試建立簡單的故障預警。

**資料包含：**  
感測數據（telemetry）、錯誤紀錄（error）、維修紀錄（maint）、故障紀錄（failure）以及設備主檔（machines）。

**本專案目標為：**  
- 建立多表資料整合流程（SQL）
- 轉換為可分析的結構（中間表 / 分析表）
- 分析設備故障分布與影響因素
- 探索故障前兆（pre-failure pattern）並建立簡單預警規則

---

## 分析內容
- 哪些機台較容易發生故障？  
- 故障是否集中在特定零件（comp）？  
- 不同機型（model）與機齡（age）是否影響故障？  
- 故障發生前是否存在可觀察的異常訊號？  

---

## 資料處理
- **原始表**：
  - `PdM_telemetry`：感測（電壓、轉速、壓力、振動）
  - `PdM_errors`：錯誤紀錄
  - `PdM_maint`：維修／零件更換
  - `PdM_failures`：故障更換
  - `PdM_machines`：設備主檔（model、age）
- **時間與資料篩選**：
  - 發現 2016-01 資料短缺，且維修資料為 2014-06 至 2016-01，為與其他資料（2015 年）時間對齊並避免數據異常，本專案僅使用 2015 年數據。
- **時間粒度與關聯**：
  - 統一整理為「每日 × 機台」（`machineID` + 日期）。

---

## SQL 資料表設計

### 中間表
- `int_daily_machine_summary`：每日 × 機台  
  彙總當日感測平均值、維修次數、故障次數、錯誤次數，並帶入機型與機齡。

### 分析表（Mart）
- `mart_machine_failure_summary`：每台機器彙總（誰常壞、零件／錯誤結構）。
- `mart_monthly_failure`：每月 × 機型彙總（趨勢與機型差異）。

## Python 圖表分析

- **01_models_overview**：
  - 以機型來看，故障集中在 model1 與 model2；與機齡沒有明顯相關。
- **02_monthly_overview**：
  - 以月份來看，除 1 月份略高外，其餘月份故障數量大致平穩（2015 年全年約 761 筆），沒有季節性爆量狀況。
- **03_machine_overview_Top20**：
  - 故障最多的 Top 20 機台主要也是 model1 與 model2，零件壞掉的組合比較分散。
- **04_comp_overview**：
  - 全廠設備中，comp2 的故障次數與「故障／維修比」皆最高，相較其他零件，其更換較常伴隨故障事件，因此後續將 comp2 列為優先關注對象。
- **05_pre_failure_Change**：
  - 比較「故障前 1~3 天」與「故障前 4~6 天」的感測數據變化，發現四大零件壞掉前都有明確的異常特徵：
    - **Comp1**：電壓（volt）平均上升約 7%，且 error1 發生頻率增加。
    - **Comp2**：轉速（rotate）平均下降約 10%，壓力與震動微幅上升，伴隨 error2 與 error3 增加。
    - **Comp3**：壓力（pressure）平均上升約 15%，同時 error4 發生頻率增加。
    - **Comp4**：震動（vibration）平均上升約 15%，同時 error5 發生頻率增加。
  - 觀察到不同零件在故障前呈現不同的感測與錯誤訊號變化，因此後續針對各零件建立不同的預警條件。
- **06_failure_warning**：
  - 預警條件是先依前述故障前 1～3 天與 4～6 天的差異分析，選出各零件較明顯的 telemetry 與 error 特徵，再設定簡單門檻建立規則，針對四個零件設計簡單的規則式預警（Rule-based），提前 1~2 天發出告警。

**預警模型表現：**

| 零件 | Precision (精準率) | Recall (捕捉率) | F1-Score |
| :--- | :--- | :--- | :--- |
| **comp1** | 38.34% | 86.46% | 53.12% |
| **comp2** | 35.92% | 94.98% | 52.13% |
| **comp3** | 36.93% | 86.26% | 51.72% |
| **comp4** | 40.76% | 95.53% | 57.14% |

## 結論
1. **風險分佈**：故障主要集中在 model1 與 model2 機型，與機齡和月份關係不大。
2. **零件特性**：comp2 是最需要關注的零件（大多是故障後才更換）；但在高故障機台上，各零件壞掉的狀況比較平均。
3. **預警效果**：依故障前觀察到的感測與錯誤訊號建立簡單規則後，各零件 Recall 約為 86%～95%，但 Precision 約為 36%～41%。結果顯示這套規則偏向「降低漏報」的設計，可以捕捉多數故障，但仍存在一定程度的誤報，較適合作為基礎預警機制，而非直接取代人工判斷。

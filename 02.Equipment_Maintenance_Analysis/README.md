# 02. Equipment_Maintenance_Analysis

## 專案說明
本專案使用 Microsoft Azure 提供的 Predictive Maintenance 公開資料，模擬工業設備維運情境，進行設備故障與維護分析。

資料包含感測數據（telemetry）、錯誤紀錄（error）、維修紀錄（maintenance）、故障紀錄（failure）以及設備主檔（machine）。

本專案目標為：

建立多表資料整合流程（SQL）
轉換為可分析的結構（中間表 / 分析表）
分析設備故障分布與影響因素
初步探索故障前兆（pre-failure pattern）

---

## 分析內容
哪些機台較容易發生故障？
故障是否集中在特定零件（component）？
不同機型（model）與機齡（age）是否影響故障？
故障、錯誤與維修之間的關係為何？
故障發生前是否存在可觀察的異常訊號？
---

## 資料處理
- 原始表：
  - `PdM_telemetry`：感測（電壓、轉速、壓力、振動）
  - `PdM_errors`：錯誤紀錄
  - `PdM_maint`：維修／零件更換
  - `PdM_failures`：故障更換
  - `PdM_machines`：設備主檔（model、age）
- 時間粒度：先統一到「每日 × 機台」
- 關聯鍵：`machineID` + 日期

---

## SQL 資料表設計

### 中間表
- `int_daily_machine_summary`：每日 × 機台  
  彙總當日感測平均值、維修次數、故障次數、錯誤次數，並帶入機型與機齡

### 分析表（Mart）
- `mart_machine_failure_summary`：每台機器彙總（誰常壞、零件／錯誤結構）
- `mart_monthly_failure`：每月 × 機型彙總（趨勢與機型差異）

SQL 階段目前已完成。

小結
故障風險主要集中在 model1／model2 及其高故障機台；與機齡、月份關係較弱。
零件方面，全隊較需關注 comp2，但高故障機台上並非單一零件主導，結構較分散


2015 年故障約 761 筆，除 1 月略高外，其餘月份大致落在相近區間，整體沒有明顯爆量月份。後續改以機台與零件結構為主分析。

部分零件的故障更換占比偏高，顯示其更換較常由故障驅動，而非計畫性更換。後續可列為重點關注零件；至於要提高預防更換，或維持備品＋故障更換，需搭配停機成本與產線影響才能決定。
四類零件的更換次數接近，但故障占比不同。comp2 故障次數與故障／更換比皆最高，顯示其更換較常由故障驅動；comp3 則相對最低。後續可優先關注 comp2 的故障模式與出現機台，是否集中在 model1／model2 的高故障機。


在進行故障預測分析前，先針對故障事件進行資料清理。
由於同一設備可能在短時間內重複發生相同零件故障，為避免將同一問題重複計算，先針對連續發生的故障進行去重處理。

此外，資料中也觀察到同一天可能出現多個不同零件（component）的故障事件，這會導致故障前特徵難以歸因至單一零件，因此在本次分析中先將多重故障事件排除，以確保分析的解釋性。

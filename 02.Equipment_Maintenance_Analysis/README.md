# 02. Equipment Maintenance Analysis

## 專案說明

本專案使用 Microsoft Azure Predictive Maintenance 公開資料，模擬工業設備維運情境，分析設備故障分布、零件故障特性與故障前的異常變化，最後嘗試建立簡單的規則式預警。

資料包含：

- `PdM_telemetry`：感測資料（電壓、轉速、壓力、振動）
- `PdM_errors`：錯誤紀錄
- `PdM_maint`：維修／零件更換紀錄
- `PdM_failures`：故障紀錄
- `PdM_machines`：設備主檔（model、age）

本專案主要練習：

- 使用 SQL 整合多張設備維運資料
- 建立中間表與分析用 Mart
- 使用 Python 分析設備故障與故障前兆
- 根據觀察到的異常特徵建立簡單預警規則
- 使用 Power BI 製作設備維運與單機分析儀表板

---

## 分析問題

- 哪些機型與機台較容易發生故障？
- 故障是否集中在特定零件（component）？
- 機型（model）與機齡（age）是否與故障情況有關？
- 故障發生前是否存在可觀察的 telemetry / error 異常？
- 能否利用這些特徵建立簡單的故障預警規則？

---

## 資料處理

### 資料範圍

資料檢查時發現：

- telemetry、error、failure 等主要資料集中於 2015 年至 2016 年初。
- maintenance 資料涵蓋較長期間。
- 2016 年 1 月資料不完整。

為統一分析期間並避免不完整月份影響，本專案主要使用 **2015 年資料**。

### 分析粒度

將不同來源資料統一整理為：

**每日 × 機台（date × machineID）**

並整合：

- telemetry 每日平均值
- error 次數
- maintenance 次數
- failure 次數
- model
- age

## SQL 資料表設計

### 中間表

`int_daily_machine_summary`

以「每日 × 機台」為粒度，整合：

- 電壓、轉速、壓力、振動每日平均
- comp1～comp4 維保次數

- 每台機器的故障、錯誤與維保彙總

`mart_monthly_failure`

- 每月 × 機型彙總

`mart_comp_summary`

- comp1～comp4 的故障與維保彙總
- 將原本的寬表整理成適合 BI 比較的結構

## Python 分析

### 01_models_overview

比較各 model 的設備數量、平均機齡、telemetry、error 與 failure。

觀察結果：

- model1、model2 的平均每台故障數較高。
- model4 平均機齡較低，但整體沒有看到機齡與故障數之間明顯的直接關係。

---

### 02_monthly_overview

分析 2015 年每月的故障、錯誤與維保情況。

- 2015 年共記錄約 761 次故障。
- 1 月故障數較高，其餘月份大致維持在相近區間。
- 未觀察到明顯的季節性故障高峰，因此後續分析轉向機型、機台與零件差異。

---

### 03_machine_overview_Top20

依設備故障次數找出高故障機台。

觀察結果：

- Top 20 高故障機台以 model1、model2 為主。
- 高故障機台的故障並非完全由單一零件造成，各 component 皆有出現。

---

### 04_comp_overview

比較 comp1～comp4 的故障與維保情況。

- 四類零件的維保次數相近。
- comp2 的故障次數最高，故障／維保比也相對較高。
- 因此後續將 comp2 列為優先觀察零件，並進一步分析各零件故障前的資料變化。

## 故障前兆分析

### 05_pre_failure_change

在進行故障前兆分析前，先針對故障事件進行整理：

- 避免短時間內重複故障造成同一事件被重複計算。
- 排除同一天發生多個不同 component 故障的事件，降低特徵歸因混淆。

接著將每次故障前的資料分為：

- **故障前 1～3 天**
- **故障前 4～6 天**

比較兩段期間的 telemetry 與 error 變化。

觀察到：

- **Comp1**：電壓（volt）平均上升約 7%，error1 發生頻率增加。
- **Comp2**：轉速（rotate）平均下降約 10%，壓力與震動微幅上升，並伴隨 error2、error3 增加。
- **Comp3**：壓力（pressure）平均上升約 15%，error4 發生頻率增加。
- **Comp4**：震動（vibration）平均上升約 15%，error5 發生頻率增加。

不同零件在故障前呈現不同的 telemetry 與 error 變化，因此後續依各零件特徵建立不同的預警條件。

---

## Rule-based 故障預警

### 06_failure_warning

依前面的故障前兆分析，挑選各 component 較明顯的 telemetry 與 error 特徵，設定簡單門檻建立 Rule-based 預警。

預警目標以：

**提前 1～2 天捕捉可能發生的故障**

為主。

### 預警結果

| 零件 | Precision | Recall | F1-Score |
| :--- | ---: | ---: | ---: |
| comp1 | 38.34% | 86.46% | 53.12% |
| comp2 | 35.92% | 94.98% | 52.13% |
| comp3 | 36.93% | 86.26% | 51.72% |
| comp4 | 40.76% | 95.53% | 57.14% |

目前規則的 Recall 約為 **86%～95%**，能捕捉大部分故障事件；Precision 約為 **36%～41%**，代表仍存在一定程度的誤報。

因此這套規則較偏向：

**優先降低漏報，再接受一定程度的誤報。**

目前僅作為基礎預警邏輯的測試，尚未使用機器學習模型。

## 結論

1. **機型差異**  
   model1、model2 的平均每台故障數較高，高故障 Top 20 機台也主要集中在這兩種機型；目前未觀察到機齡與故障數之間明顯的直接關係。

2. **時間分布**  
   除 1 月故障數較高外，其餘月份大致維持相近水準，未發現明顯的季節性高峰。

3. **零件差異**  
   comp2 的故障次數與故障／維保比相對較高，是本資料中較值得優先關注的零件。

4. **故障前兆**  
   comp1～comp4 在故障前分別呈現不同的 telemetry 與 error 變化，顯示不同零件可能需要使用不同的預警條件。

5. **預警結果**  
   Rule-based 預警的 Recall 約為 86%～95%，Precision 約為 36%～41%。目前規則較偏向降低漏報，可作為基礎預警機制，但仍需要進一步降低誤報，不能直接視為完整的故障預測模型。
